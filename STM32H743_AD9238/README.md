# STM32H743 + AD9238：2026 G 题配套工程

这是从 `STM32H743` 独立复制并改名得到的 AD9238 配套版本；原 STM32 工程未被本次迁移覆盖。它与同级 `FPGA_BX71_AD9708_AD9238` 成套使用，不能与旧 AD9280 FPGA 镜像混用。

## 为什么 STM32 也需要新副本

ACM9238 把 ADC 从 8 位/32 MSPS 改为 12 位/50 MSPS，FPGA 的 G 题抽取比随之从 16 改为 25。虽然 STM32 最终仍接收 2 MSPS、16 位有符号 Q8.8 数据，但设备身份、协议版本、触发阈值位宽和物理 LSB 都发生了变化，因此必须同步修改驱动。

配套参数：

| 项目 | AD9238 版本 |
|---|---:|
| ADC 物理采样率 | 50,000,000 sample/s |
| 原生分辨率 | 12 bit |
| G 题数字链 | FIR307 + CIC3/R25 |
| STM32 分析流 | 2,000,000 sample/s |
| FPGA 设备 ID | `0xAD923801` |
| FPGA 协议版本 | `0x00020002` |
| 触发寄存器 | 模式 `[17:16]`，阈值 `[11:0]` |
| 标称原生 LSB | `10/4096 V` |
| Q8.8 传输 LSB | `10/65536 V` |

这里的 16 位传输没有把 AD9238 截回 8 位：12 位原生有符号码经 FIR307 生成 signed Q4，再进入 CIC；抽取器输出仍保留这 4 个分数位。因此 STM32 获得的是“12 位 ADC 信息 + 4 位 CIC 分数精度”，标称传输步距约 `0.152588 mV`。改成更宽的 SPI 样本不能修复百分比型的整链路增益误差。

## 主要文件

- `Modules/ad9238.c/.h`：FPGA 寄存器驱动、设备/协议核验、12 位触发配置、Q8.8 解码。
- `Modules/ad9238_app.c/.h`：0…4095 原生码的电压标定和阻塞采集流程。
- `BSP/signal_adc_ad9238.c`：G 题通用采样后端，固定 50 MHz/R25→2 MHz。
- `MDK-ARM/STM32H743_AD9238.uvprojx`：已重命名的 Keil 工程与目标。
- `STM32H743_AD9238.ioc`：已重命名的 CubeMX 工程描述。

`SignalAdc_*` 与上层 `g_contest_app`、周期信号分析和显示接口保持不变，因此 G 题业务代码不需要知道底层 ADC 型号。初始化时会严格检查设备 ID、协议版本、50 MHz 采样时钟、16 位样本字和 8 位小数位；旧 FPGA 镜像会被拒绝。

## STM32 ↔ BX71 SPI

沿用现有 P2 连接：

| STM32H743 | BX71 P2 FPGA | 作用 |
|---|---|---|
| SPI2_SCK | K19 / GPIO0_26 | SCK |
| SPI2_MOSI | L19 / GPIO0_32 | MOSI |
| SPI2_MISO | K17 / GPIO0_28 | MISO |
| CS GPIO | K18 / GPIO0_29 | CS_N |
| IRQ GPIO | L16 / GPIO0_30 | FPGA ready/IRQ |
| GND | GND | 共地 |

ACM9238 与 BX71 的 P3 直插连接由 FPGA 工程约束管理；STM32 不直接连接 D0…D11 或 ADC 时钟。

## 串口调试反馈

USART1 使用 115200 8N1。输入 `HELP` 可查看命令；输入 `ADCDBG` 会输出最近一次缓存的 AD9238/FPGA 调试快照，包括设备 ID、协议版本、物理采样时钟、Q8.8 字宽、R25 配置、触发状态、采集/读取计数、OTR 计数以及 min/max/latest/mean。该命令不会发起新的 SPI 事务，也不会移动 FPGA 块 RAM 读指针，适合在采集成功、超时或链路错误后留存现场。

上电初始化成功时还会主动输出 `0xAD923801`、协议 `0x00020002`、`S16Q8` 和 ready 状态，便于在测试前立即发现烧错 FPGA 镜像或时钟未锁定。

## 高频偏差、联合补偿与第三问抗干扰

两组 400 kHz 数据的相对增益分别为 `147.838654/140=1.055990` 和 `200.661011/190=1.056111`，只相差约 `0.0114%`。因此绝对误差随幅度同比增加属于稳定乘性增益，不是削顶、FFT 窗、整数溢出或幅度相关非线性。

这个偏差并非全频统一：100 kHz 平均增益约 `1.000056`，200 kHz 约 `1.057995`，400 kHz 约 `1.056050`。软件不能用一个全局系数压低原本准确的 H1，而是分两层处理：

1. **确定性数字响应补偿。** `PeriodicAnalyzer_GetFir307Correction` 按 FPGA 的 154 个 Q16 对称系数求精确幅频响应；CIC 补偿严格匹配 signed-Q4 RTL 的 `274878/2^32` 倒数。业务路径同时启用两者，幅值修正为 `1/(|H_FIR|*|H_CIC|)`，相位修正对应 FIR 153 + CIC 38 = 191 个 50 MHz 时钟。
2. **整链路残差表。** 100/200/400 kHz 使用用户两次实测的 `Aref/Ameasured`；200–400 kHz 已呈稳定平台，因此增加 500 kHz 端点保持 400 kHz 倍率。该 500 kHz 点明确是平台推断值，不伪装成实测，仍需上板扫频确认。

| 频率 | 参考值 | 补偿前读数 | 残差倍率 |
|---:|---:|---:|---:|
| 100 kHz | 25 mVpp | 25.002010 / 25.000788 mVpp | x0.999944044 |
| 200 kHz | 12.5 mVpp | 13.232144 / 13.217731 mVpp | x0.945184332 |
| 400 kHz | 140 / 190 mVpp | 147.838654 / 200.661011 mVpp | x0.946924430 |
| 500 kHz | 待实测 | 沿用 200–400 kHz 平台 | x0.946924430（推断） |

低于 100 kHz 不外推残差倍率；100–400 kHz 仅在实测点间插值，400–500 kHz 明确保持最后实测倍率并标为推断。串口 `[SPEC]` 格式不变，新增 `[RESP]` 会分别输出 `transport_vpp_mV、fir_x、cic_x、digital_x、after_digital_vpp_mV、chain_x、total_x、final_vpp_mV、chain_status`；状态为 `TABLE、INFERRED_HOLD、UNCAL`，不会把 500 kHz 推断端点伪装成实测。

为满足第三问，FPGA 已在 50 MSPS 抽取前加入 307 taps 线性相位低通，阻带从 1 MHz 开始；这样 1.6 MHz 干扰不会先混叠成 400 kHz。FIR 独立位精确仿真中，约 200 mVpp 的 1–10 MHz 干扰残余均低于 0.4 mVpp。Host 联合响应回归覆盖 10/100/200/300/400/450/500 kHz；500 kHz、200 mVpp 单音恢复为 `199.998 mVpp`，相位误差 `0.00010 rad`；含 500 kHz/190 mVpp 分量的多音完整波形 Vpp/RMS 数值误差均小于 `0.001 mV`。这些是 RTL/算法模型结果，实板仍必须验证题目要求的 5 mV 指标和 2 s 时限。
## 串口屏显示

`BSP/g_tjc_ui.c/.h` 已同步 AD9280 最新稳定实现：恢复波形/频谱横向翻转修复，加入波形时间窗和频谱纵轴自适应范围，并保留透明批量 `addt` 传输、FE/FD 应答和链路健康状态。ADC 驱动、设备 ID 与 CIC 参数仍全部来自 AD9238 专用工程，没有复制 AD9280 的采样代码。
## 使用边界

代码和 Keil 构建通过不代表已经烧录 STM32，也不代表 ACM9238 模拟幅值精度已经达到 G 题 5 mV 指标。首次上板必须与 AD9238 FPGA 镜像配套，先核对设备 ID/版本，再用已知直流与周期信号做零点、增益和频响标定；标称 ±5 V/`10/4096 V` 只用于初始换算，不能替代实测校准。
